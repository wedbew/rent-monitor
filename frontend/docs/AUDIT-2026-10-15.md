# Frontend implementation audit — 15 October 2026

## Verdict

**Strings do not come from translation files. Number presentation only partially uses Intl. The frontend needs its
own enforced CI pipeline.** There is a good foundation, but passing the current unit tests does not establish
production readiness. Session cleanup, failed sign-out, duplicate submissions and ambiguous analysis recovery
deserve attention before additional product features.

This is an audit and remediation proposal; application code and workflows were not changed. For the current status
of each finding, read the re-verification section first.

## Findings

### F01 — P1 — GitHub does not enforce frontend quality checks

**Confirmed.** `.github/workflows/ci.yml` runs Python checks and checks only that two historical frontend finance
filenames do not exist (line 33). No workflow installs the SPA toolchain or runs its typecheck, lint, build, unit or
browser suite. `scripts/ci_local.sh:83` has frontend stages, but local execution cannot protect remote merges.
`security.yml` scans Python dependencies; `.github/dependabot.yml` has no npm entry. `docs/STATUS.md` already
identifies GitHub lanes as follow-up #296.

**Impact:** TypeScript/build failures and browser regressions can merge while the existing backend checks stay green.
**Action:** Implement the separate pipeline below, add npm advisory monitoring, and require its final gate in branch
protection. Do not equate workflow-file presence with an enabled required check.
**Acceptance:** A PR with invalid TS, a failing browser assertion or stale generated client fails the frontend gate.

### F02 — P1 — Session revalidation can preserve the previous person's tenant state

**Reproduced.** `shell/session.tsx:23` returns `null` directly on `/api/me` 401, bypassing the expiry event in
`api/client.ts:83`. The provider renders signed out but does not call `endSession`, clear tenant queries or run
stream cleanup. `startSession:50` and the other-tab signed-in handler at line 79 also replace/invalidate only the
session query; they do not compare user identity and purge the old person's state.

**Impact:** Cached audits can survive expiry and appear after another account signs in in the same tab; an account
switch in another tab also risks reusing identity-independent audit keys. This concerns browser memory/cache;
the review did not demonstrate a backend authorization bypass.
**Action:** Centralize transitions to signed out and changes of authenticated user id; cancel old work, clear tenant
queries/mutations and run resource cleanup before exposing the new identity. Namespace tenant query keys too.
**Acceptance:** Populate account A's cache, expire via session revalidation, sign in as B, and assert that no A query
or stream survives. Cover an account switch announced by another tab and late completions.

### F03 — P1 — Failed sign-out is presented as successful

**Confirmed control flow.** `shell/AccountBlock.tsx:28` calls `endSession` and broadcasts signed out in `onSettled`,
including when the POST never reaches the server. The HttpOnly cookie then remains valid. Contrary to the comment,
a later request need not return 401: session revalidation or reload can sign the person straight back in.

**Action:** Clear displayed tenant data immediately, but retain a visible local locked/sign-out-pending state when
revocation fails, offer a retry, and do not silently resume the session. Announce success only after revocation is
confirmed. Define how the pending state behaves across reloads without storing a session credential.
**Acceptance:** Drop the sign-out request before delivery; focus/reload the tab and verify the UI does not claim
the server session was revoked or silently restore private content.

### F04 — P1 — Busy submit buttons do not prevent native form submission

**Reproduced.** `ui/Button.tsx:55` sets `aria-busy` and removes `onClick`; it neither disables the button nor
prevents its default submit behavior. `LoginPage.tsx:30`, `SignupPage.tsx` and `PasswordPages.tsx` lack a pending
guard in their submit handlers. Clicking again or pressing Enter can therefore issue another login/mail/reset
request. The new analysis form has a pending guard, but the shared primitive's guarantee is false.

**Action:** Prevent busy activation using a deliberate accessible disabled/busy policy and guard each mutation
submission, including implicit Enter submission. For costly creation, retain server-side deduplication and use
request idempotency where the API supports it.
**Acceptance:** Delay every relevant POST; repeated clicks and Enter produce exactly one request while pending.

### F05 — P1 — Ambiguous analysis recovery can identify an unrelated audit as the submitted one

**Confirmed, uncommitted implementation.** `features/analyses/new/useCreateAudit.ts:37` searches only the latest
five analyses and accepts the first timestamp newer than `since - 60_000`. It does not correlate the submitted
listing or a request identity. A different listing analyzed moments earlier, or a concurrent tab, can be reported
as "Analiza została przyjęta" after this request actually failed. Clock skew and the five-item window also make
absence inconclusive.

**Action:** Prefer a server-supported idempotency/correlation key. Until available, treat reconciliation as
uncertain; show candidate analyses without asserting that this submission succeeded. Listing/time matching alone
cannot establish request identity.
**Acceptance:** Include an unrelated recent audit, concurrent submissions, clock skew and a delayed list result.

**Confirmed.** No locale catalog, translation loader or translation lookup exists. Polish text lives in JSX,
template strings and lookup tables. `api/problems.ts` centralizes error copy but is still a source-code table,
not a translation-file system. Representative inventory:

| Authentication | `features/auth/{LoginPage,SignupPage,PasswordPages,LinkPages}.tsx`: labels, instructions, success notices                        |
| Validation     | `features/auth/forms.ts:15`: email/password errors and retry-time sentences                                                      |
| Analyses       | `features/analyses/AnalysisPage.tsx`, `status.ts`, `new/NewAnalysisPage.tsx`, `progress/frames.ts`: statuses, stages and notices |
| Navigation     | `shell/navigation.ts:30`: labels; shell/layout/menu/theme/session components: accessible names                                   |
| Shared UI      | `ui/Dialog.tsx`: default close label; `ui/Field.tsx`: hidden "Błąd" prefix; `ui/FormErrors.tsx:31`: summary                      |

translation extraction. Avoid concatenated translated sentence fragments. Add literal/key/placeholder checks.

The plan at `docs/FRONTEND-PLAN.md:46` deliberately deferred a translation framework. This finding records the
gap against the requested standard, not a claim that the implementation violated that earlier decision.

### F07 — P2 — Intl use is partial; numeric formatting and pluralization are not locale-driven end to end

**Confirmed, with reproduced counterexamples.** `api/format.ts:36` uses `Intl.NumberFormat` for the integer part
of decimals; it manually assembles comma, sign, fraction, `zł`, `%` and `m²`. Dates correctly use
`Intl.DateTimeFormat` with Europe/Warsaw. `plural:116` implements Polish rules manually.

| Numeric surface                                      | Current behavior                                                                    | Recommended boundary                                                                |
| ---------------------------------------------------- | ----------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| Money                                                | Exact decimal-string/BigInt rounding, Intl integer grouping, manual currency output | Exact decimal string into an Intl currency formatter; preserve rounding/sign policy |
| Ratios                                               | Custom decimal shift and manual `%`                                                 | Intl percent formatting on the original exact ratio string                          |
| Area/plain decimals                                  | Custom fraction/comma; manual area suffix                                           | Intl decimal/unit formatting, or documented custom square-metre label               |
| Report/analysis counts                               | Raw `${count}` in `formatReports:124` / `formatAnalyses:128`                        | Intl integer formatting plus plural message selection                               |
| Retry time                                           | Raw seconds/minutes in `features/auth/forms.ts:48`                                  | Formatted count and translated grammatical message                                  |
| Progress                                             | Raw `${progress.pct}%` in `AnalysisPage.tsx`                                        | Shared integer-percent display helper                                               |
| Form limits/error count                              | Raw interpolation in `forms.ts`, `NewAnalysisPage.tsx`, `ui/FormErrors.tsx:31`      | Numeric placeholders through the presentation boundary                              |
| IDs, CSS percentages, API event ids, limits/timeouts | Machine values                                                                      | Keep machine syntax; do not localize                                                |

For example, `formatReports(1234)` returns `1234 raporty`, bypassing grouped Intl display. Ordinary small counts
look fine, so existing examples do not reveal this gap.

**Clarification:** Intl.NumberFormat formats numbers; it is not a parser for localized user input. Canonical API
decimal strings must remain exact. Do **not** replace BigInt handling with `Number(decimalString)` or
`parseFloat`. Modern ECMA-402 accepts exact numeric strings for formatting; verify this in every supported
browser and adapt TypeScript typings at one tested boundary if necessary. Preserve the existing deliberate
Unicode minus/rounding policy explicitly if product design requires it. Use `Intl.PluralRules` with translated
grammatical forms, including `other` where applicable; relative-time APIs do not necessarily produce the exact
retry wording the product wants. [ECMA-402](https://tc39.es/ecma402/#sec-intl-numberformat-prototype-format)

**Acceptance:** Test large exact decimals, half rounding, negative zero, missing/invalid data, zero and Polish
1/2/5/12/22/112 counts, and a second test locale. Verify supported browsers rather than assuming Node behavior.

### F08 — P2 — Body parsing falls outside transport error normalization

**Reproduced.** `api/client.ts:46` races the fetch until response headers arrive. `openapi-fetch` reads the body
after that wrapper returns. A slow body aborted by the retained timer throws a raw `AbortError`, bypassing
`TransportError("timeout")`; invalid JSON similarly bypasses the transport mapping. A synthetic non-cooperative
body remained pending beyond the deadline. This does not prove native browser fetch ignores cancellation.

**Impact:** Timeout messages/retry policy/reconciliation see the wrong error kind. Timers and caller listeners
also remain after fast successful requests until the deadline because cleanup is only in `catch`.
**Action:** Bound and normalize the whole response/body lifecycle and clean up in a finalization path after
consumption. Preserve caller cancellation versus timeout and classify decoding failures explicitly.
**Acceptance:** Headers arrive immediately, body stalls, disconnects, or returns invalid JSON; verify error kind,
deadline and cleanup, including a caller signal already aborted before invocation.

### F09 — P2 — Reconnecting streams can leave an analysis stale indefinitely

**Confirmed, uncommitted implementation.** `progress/streams.ts:69` treats native EventSource CONNECTING as
reconnecting indefinitely. `AnalysisPage.tsx` enables polling only for `failed`; `queries.ts` polls only when that
flag is true. A long outage or proxy that accepts a connection but stops delivering progress can leave the view
stale indefinitely even if the job finished. Normal reconnects and permanently CLOSED streams are covered.

**Action:** Add a reconnect/inactivity deadline with a heartbeat-aware watchdog or periodic authoritative status
refresh while active; close redundant streams and stop polling on terminal state/unmount/sign-out. Deduplication
does not replace liveness detection.
**Acceptance:** Sustain CONNECTING and an open but silent stream past the threshold, then verify the final API
status and balance appear. Also test missing terminal frames and a 401 during streaming.

### F10 — P2 — Query cancellation is not passed to HTTP requests

**Confirmed.** `shell/session.tsx:23` and `features/analyses/queries.ts` query functions ignore the TanStack query
context's AbortSignal, although `createApi` accepts one. `clearTenantState` cancels queries, but cannot stop those
fetches at the transport layer. TanStack's internal cancellation behavior should not be confused with actual
network cancellation.

**Action:** Pass `queryFn({ signal })` into each GET. Guard outstanding mutation and reconciliation callbacks with
a session generation so old work cannot navigate or invalidate a newly signed-in person's state.
**Acceptance:** Switch route/account during delayed reads and creation; verify aborted HTTP and no late navigation.
[TanStack cancellation guide](https://tanstack.com/query/latest/docs/framework/react/guides/query-cancellation)

### F11 — P2 — Runtime guards assert more than they validate

**Confirmed.** `api/errors.ts:39` checks only four fields before casting to the complete `Problem` type.
`features/auth/forms.ts:78` then assumes `errors` exists and has valid `loc` arrays: a known
`VALIDATION_ERROR` with missing/malformed `errors` can throw while rendering its error message.
`api/report.ts:44` verifies version and key presence, but accepts malformed nested values as `DealAnalysis`.
Generated TypeScript types and schema-valid test fixtures do not validate network responses.

**Action:** Validate the fields actually consumed at each untrusted boundary. Use a safe malformed-response
fallback; validate version-specific report structure before a future report renderer consumes it. Prefer generated
or narrow guards over duplicating every API schema by hand; avoid adding a heavyweight validator to every request
without measuring its cost.
**Acceptance:** Missing/non-array validation errors, malformed locations, null report blocks and wrong numeric types
produce a controlled fallback rather than a render exception. Full report display is still pending #274.

### F12 — P2 — Error announcement and focus behavior differ between forms

**Confirmed.** Login renders server field messages outside its `FormErrorSummary` list; magic-link and
forgot-password forms render validation messages without moving focus or creating an alert. In the new analysis
form, `submitCount` increments before the asynchronous field error exists; `FormErrorSummary` focuses only on
`submitCount`, so a later server error does not trigger its intended focus behavior. `TextField`'s descriptions
help when the user revisits the input, but do not guarantee an announcement when an error appears.

**Action:** Adopt one error-summary/announcement contract for client and server validation. Trigger focus when the
submit result becomes invalid, not simply when the request starts. Keep typing from stealing focus.
**Acceptance:** Keyboard and screen-reader checks for blank input, server 422/weak password, repeated errors and
general failure on every form. Automated axe checks alone do not establish this behavior.
[W3C error identification](https://www.w3.org/WAI/WCAG22/Understanding/error-identification.html)

### F13 — P2 — Coverage and browser claims exceed what the enforced metrics prove

**Confirmed.** `vite.config.ts` coverage includes only `api/**/*.ts`. Component/auth/theme tests do execute, but
the impressive percentage does not measure those areas. Playwright config covers Chromium desktop and Pixel
emulation only, while the runbook promises Firefox, Safari, iOS and Android. There are no screenshot-baseline
assertions in the reviewed browser specs. Interaction registration proves exercised controls, not all branches,
visual fidelity, real-provider behavior or keyboard/screen-reader usability.

**Action:** Add meaningful regression cases for F02–F12, scope coverage reporting to critical hooks/shell/features,
add Firefox/WebKit smoke runs, and preserve scheduled/manual real-device checks. Add stable visual snapshots for
the shell, forms, overlays and report when built. Measure critical behavior, not a percentage target alone.
**Acceptance:** Publish scope-specific reports and an explicit browser/device evidence matrix; retain traces on failure.

### F14 — P2 — SPA hosting, CSP and release handling remain unimplemented

**Confirmed release gap, planned #281.** `deploy/Caddyfile:17` uses `default-src 'none'`; its fallback responds 404
and no static SPA is served. The Python Dockerfile does not build/copy frontend output. Vite preview tests do not
exercise Caddy's security policy, caching or deep-link fallback. Simply copying `dist` into the current container
would not make this configuration serve the application.

**Action:** Deliver a separately built static artifact with Caddy serving assets/deep links, retaining API/SSE
routes and Python-only server runtime. Define script/style/connect/frame/image allowances for actual providers,
cache HTML and theme bootstrap for revalidation and fingerprinted assets immutably; do not turn missing JS assets
into an HTML fallback. Audit the dynamic progress `style` updates against the chosen CSP. Keep deployed HTML and
assets coherent during rollout/rollback. Do not broadly relax CSP to make tests pass.
**Acceptance:** Test the production Caddy image: login/deep-link reload, assets/MIME, API 404 preservation,
SSE, security headers, Google integration where configured, cache headers and rollback/chunk recovery.

### F15 — P2 — Browser observability is absent

**Confirmed release gap, planned #280.** `RouteError.tsx` renders recovery UI but reports no diagnostic event;
`main.tsx` has no browser error/rejection integration. API errors expose a request id, which is useful, but unexpected
render/chunk/stream failures cannot currently be correlated from client telemetry.

**Action:** Implement the planned release-tagged reporting with URL/fragment, email, listing text and credential
redaction; verify failure sampling and data minimization. Do not add analytics merely to tick a quality box.
**Acceptance:** A synthetic render failure reaches the selected sink with a release id and useful scrubbed context;
secret/token/email test values do not. No external reporting was exercised in this audit.

### F16 — P2 — Numeric edge handling and finance lint boundaries need tightening

**Reproduced/confirmed.** `formatArea("abc")` produces `nie obliczono m²`, adding a unit to an invalid value.
`formatRatio`/`formatDecimal` accept unrestricted precision arguments; invalid values can reach BigInt exponent
operations and throw. The ESLint `Number` selectors match certain direct member names only: aliases,
destructuring, arithmetic and other coercions bypass them. The finance file guard in CI/hooks checks obsolete
`frontend/src/lib/...` paths rather than the actual shallow layout or financial calculations generally.

**Action:** Normalize invalid formatter results before appending units, restrict precision to supported bounded
integers, and add rule tests with representative bypasses. Treat lint as a guardrail backed by review/domain
boundaries; no filename ban can prove the absence of financial calculations.
**Acceptance:** Invalid area/precision never generates misleading text or an unhandled exception; lint fixtures
cover direct access, aliases, computed access and coercions. No financial engine math was found in inspected UI code.

### F17 — P3 — All routes ship eagerly and the bundle budget is advisory

**Confirmed.** `routes.tsx` statically imports every page. The measured JS entry is 152.51 kB gzip, under the
runbook's 200 kB provisional budget, but `check-dist.mjs` checks forbidden content only and enforces no size limit.
This is a growth risk, not evidence that the current bundle is slow.

**Action:** Before heavy report/chart/tool features land, split route code where measurement justifies it and
enforce the agreed entry/total transfer budget. Track loading and interaction performance using repeatable lab
measurements; no Core Web Vitals or Lighthouse score was measured here.

### F18 — P3 — Product completeness and documentation need an explicit release checklist

**Confirmed release gaps.** Analysis list, credits/checkout, settings and public documents are `PendingPage`
routes; the new analysis success view shows status/credit outcome but no report yet. These correspond to planned
slices (#274–#279 and blocked tools), not completed-product regressions. Current purchase/recovery links can
therefore lead to a placeholder. `frontend/README.md` both says Storybook is added by #270 and later explains it is
deliberately deferred. The frontend row in `docs/STATUS.md` mixes authorization granted with old wording that it
still awaits authorization.

**Action:** Mark all dependencies and user-visible dead ends explicitly before a release; make the runbook and
status description agree. A component catalog can help reuse, but adding Storybook is not itself a correctness
requirement. Maintain the shallow domain-free primitives, CSS modules and semantic tokens already present.

## Proposed frontend pipeline

**Recommendation:** Separate frontend verification from backend verification; keep contract and journey work as
shared integration gates. This does not require a separate repository, production Node service or independent
uncoordinated releases. No workflow or branch protection was changed by this audit.

| Lane / proposed stable check  | Inputs and work                                                                                                                        | When                                                                          |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| `frontend-quality`            | Pinned Node/pnpm, frozen install, generated API/report drift, TS, ESLint, CSS, formatting, Vitest, build, dist scan and bundle budgets | Frontend/config/schema PR changes                                             |
| `frontend-browser`            | Built SPA, mocked API, interaction/popup gate and axe; Chromium widths; Firefox/WebKit critical smoke                                  | PR changes affecting frontend/contracts/test tooling                          |
| `frontend-journey`            | Frontend artifact with isolated Compose Postgres/API/worker and fake providers; session and analysis journey                           | PRs affecting frontend, contracts, auth/audits, worker behavior or deployment |
| `frontend-security`           | Lockfile/advisory scan, install-script policy, secret scan; npm Dependabot to staging                                                  | Dependency changes and scheduled advisory refresh                             |
| `frontend-gate`               | Always-created aggregate; distinguishes deliberately unchanged lanes from required failures, cancellations or unexpected skips         | Every relevant PR / merge queue if enabled                                    |
| Static artifact/release smoke | Build once from approved commit, manifest/digest, Caddy serving/header/deep-link/SSE smoke, rollback verification                      | Approved deployment path (#281)                                               |

Implementation details that matter:

- Use SHA-pinned Actions, `contents: read`, no secrets for PR-code jobs, credential-free checkout, concurrency
  cancellation and explicit timeouts. Cache package downloads with the lockfile/toolchain identity.
- Classify paths inside an always-running workflow; do not apply top-level `paths` filters to the sole required
  check, which can leave that check pending. Include `frontend/**`, both schema files/generators, relevant
  backend contracts/routes/worker behavior, Compose/Caddy, CI scripts and workflow configuration. A shared contract
  change must run both appropriate backend validation and frontend drift/compatibility checks.
- Keep the backend's existing tests/invariants/migrations required. Frontend changes should not require rebuilding
  Python environments for independent lint/unit checks; integration changes must still prove both sides.
- Use unique ports/project names, test databases, Playwright output directories and `E2E_COVERAGE_DIR`; disable
  reuse of unrelated preview servers in CI. Browser attempts in this audit demonstrated why ownership matters.
  Upload bounded/redacted traces and reports.
- Make the aggregate fail on a needed lane's failure, cancellation or unintended skip; branch protection must
  require the stable aggregate. Include merge-queue events if the repository enables a queue.
- `pnpm check` does not run Playwright. Invoke browser and real-stack journey scripts explicitly. The local
  sample comparison is useful but may report SKIPPED without `data/`; CI should rely on committed schema/fixture
  validation rather than a developer's untracked capture.
- Add typed translation-key/interpolation checks and visible-literal rules when extraction is implemented;
  formatter tests should establish exact-decimal safety and consistent Intl display.

GitHub documents path-filter behavior and required checks in
[workflow syntax](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#onpull_requestpull_request_targetpathspaths-ignore).
Read this as a proposed design; current remote ruleset configuration was not inspected.

## Practices worth preserving

- Same-origin relative API calls and HttpOnly session model; no client session-token storage.
- Fragment-token removal before rendering, safe redirect handling, no raw HTML rendering and privacy-conscious
  tab signals. Server enforcement of cookie/Origin/tenant policy remains essential and was not re-audited here.
- Typed generated contracts, exhaustive problem-code copy, version-aware report entry point and sanitized fixtures.
- Decimal strings preserved through display formatting; explicit missing values, deterministic rounding and Warsaw dates.
- Query retries limited to transient reads; mutations do not automatically retry; balances come from the server.
- Semantic headings/landmarks, skip links, field labels/descriptions, real navigation links, Base UI dialogs,
  reduced motion, theme persistence, design tokens and isolated component styles.
- Scenario-driven browser tests, interaction/popup inventory, axe checks and dist checks already provide useful
  protection once enforced remotely. The findings above identify missing behavior rather than a reason to rewrite
  this foundation or add frameworks indiscriminately.

## Suggested remediation order

1. **Protect the current flows:** F01–F05; add regression tests for session expiry/account switching, failed sign-out,
   delayed duplicate submits and correlated/uncertain recovery.
2. **Meet the requested localization standard:** F06–F07 and F16, preserving exact monetary values and choosing
   one catalog/formatter boundary before more pages duplicate copy.
3. **Harden async/error behavior:** F08–F12; include disconnects, body timeouts, malformed data and late work.
4. **Prove release behavior:** F13–F15, production Caddy smoke and the remaining product slices in F18.
5. **Control growth:** F17 and documentation cleanup; add splitting/catalog tooling when it has demonstrated value.
