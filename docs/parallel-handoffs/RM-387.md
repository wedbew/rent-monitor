## What changed

`VisionRecord` (inside `DealAnalysis.vision`) now keeps `floor_plan_text`, `notes` and `equipment`
(`EquipmentObservation`: item, `media_ordinal`, confidence 0..1, provenance photo|floor_plan|unattributed,
`sale_status` included|visible_only|unknown). Prompt version `vision-v2`. The worker rewrites the model's
`image_index` to the ordinal in the selected media list (photos then plans, the media manifest's ordinal).
Boundary fix: `VisionOutput.photos` cap 25 -> 27 (25 photos + 2 plans); before, a full listing failed validation and
silently became `succeeded_degraded`. Malformed equipment entries are dropped, never void the answer. Evidence never
reaches a number (tests: returns byte-identical with and without equipment; clamp unchanged).

Versioning decision: **schema_version stays 1**, new fields are optional in the schema (generator `ADDITIVE_FIELDS`,
the "new optional field keeps the version" row of REPORT-SCHEMA.md). Baseline `report_schema_v1.json` untouched and
`breaking_changes()` is empty. The SPA (`frontend/api/report.ts`, version 1 only) is unaffected. Golden diff: only `tests/engine/golden/leszno_with_vision.json` gains `equipment: []`, `floor_plan_text: null`, `notes: null` (no number moved); the committed schema grows by the `EquipmentObservation` definition and
three optional `VisionRecord` properties. OpenAPI and frontend types: unchanged (verify with the generators after merge).
