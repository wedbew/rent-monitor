## [Unreleased]

### Added
- OpenAPI documents errors as they are sent: a `Problem` schema (RFC 9457 `application/problem+json`, `code` as an enum of the stable problem codes), no more `HTTPValidationError`, and for every operation the error statuses it can return with the codes that come with each (`x-problem-codes`). The `202` of `POST /api/billing/checkout` and of the admin refund is documented as a success. No behaviour change; clients generated from `docs/openapi.json` get correct error types (RM-264)
- API smoke test and sample capture: `tests/smoke/` runs one scenario registry over every operation in `docs/openapi.json` (real API, Postgres, ledger, queue worker and engine; fake providers) and checks each answer against the document, failing when a route has no scenario; `make api-samples` replays the scenarios over loopback HTTP into `data/api-samples/<UTC>/` (gitignored, 30-day retention, cookies, ids and emails redacted, `manifest.json` lists the documentation gaps) and `make api-samples-clean` deletes them. New env names `CAPTURE_ADMIN_URL` and `API_SAMPLES_LIVE_AUTHORISED` (`.env.example`). Operator action: none (RM-263)
- Error tracking is on for the beta host: `SENTRY_DSN` points at the Better Stack Errors application (set privately on the host, never committed; the Sentry SDK integration and its scrubbing are unchanged). Compose now passes `RELEASE` (the image tag) to the API and workers so events group per deploy. Operator action: none for new hosts beyond setting `SENTRY_DSN` in `.env` (RM-250)
- `scripts/push_env_to_host.sh`: owner-run helper that copies named variables from the local `.env` to the host `.env` over ssh without printing values (mode 600, optional `--restart`). `docs/PADDLE-SANDBOX-SETUP.md` lists what is ready in the Paddle sandbox (three pack products, webhook destination) and the remaining owner and agent steps. Operator action: see that document (RM-248)
- The AI budget hold before a vision call is priced from OpenRouter's public model catalog (input tokens at the model's input price, plus the `max_tokens` output ceiling at its output price, cached for an hour) instead of a flat guess; the real `usage.cost` still replaces it when the call settles. `OPENROUTER_CALL_ESTIMATE_USD` is now only the fallback when the catalog has no price. No operator action (RM-246)
- Vision and OCR stages in the audit: after `context`, the advert's photos (at most 25) and floor plans (at most 2) are downloaded from allow-listed hosts, sent to OpenRouter with a fixed prompt (images only, EXIF stripped, no listing text) within the AI budget and a 240 s stage cap, parsed into a typed answer and passed to the engine, which clamps every adjustment to +/-15 %. Progress shows `vision` and `ocr`. A missing key, spent budget, timeout or unusable answer still ends the audit `succeeded_degraded`. New settings `LEGAL_IMAGES_ENABLED` (default true; false skips the stage) and `OPENROUTER_VISION_MODEL` (placeholder `google/gemini-2.5-flash-lite`). Operator action: put `OPEN_ROUTER_API_KEY` in the host `.env` and restart the audit worker; without it nothing changes (RM-244)
- `Listing.photo_urls` and `Listing.floor_plan_urls` (https only, bounded); `scripts/live_audit_check.py` runs one real listing through the deployed stack and prints codes and numbers only (RM-244)
- Rental-comparables importer: `import_rental_city` (queue `batch`, retried with backoff) reads up to 5 Otodom flat-for-rent result pages for a city and stores one `otodom_rental` sidecar per city and month with a rent and an area per offer (no seller, id or text kept). An audit that finds no rents for the current month queues the import (one job per city and month); that audit still gets the honest refused rent. A thin or blocked import never replaces the previous month. Search fetches obey `LEGAL_SCRAPING_ENABLED`, the 1 req/s host slot and the circuit breaker. Operator action: none; the `worker-ops` lane already serves `batch` (RM-240)
- `Listing.location_id`: Otodom's city path, validated as a slug path, used to find a city's rental results (RM-240)

### Added
- Support refunds and invoices (RM-229): `POST /api/admin/billing/purchases/{id}/refund` (admin only) refunds an **unused** pack in full: it freezes the lot under the user lock, writes a durable refund intent, then asks Paddle; a pack with spent or running units goes to manual review (409 `REFUND_NEEDS_REVIEW`, nothing sent); an ambiguous result is reconciled by listing the transaction's adjustments before any second creation; units move only when Paddle reports the refund approved, a rejected one unfreezes the lot. `GET /api/billing/purchases/{id}/invoice` returns a short-lived Paddle invoice link to the buyer only (no-store, 10 per minute; foreign ids 404). New problem codes `PURCHASE_NOT_REFUNDABLE`, `REFUND_NEEDS_REVIEW`. No migration
- Provider refunds and chargebacks (RM-219): adjustment notifications, and a reconciliation pass every 15 minutes for 60 days after a grant, now apply to a granted pack. A full reversal (approved refund and/or chargeback, counted once) freezes that pack's lot, takes its still-available units back with an append-only `refund_revoke` ledger entry (the balance never goes negative; signup, admin and other packs are untouched) and marks the purchase `refunded`; units held by running audits are revoked when each is released, and units already spent put the account on a **billing hold** (`credit_account.billing_hold`) instead of a debt: new reservations and purchases answer 403 `BILLING_HOLD` until an admin clears it (`POST /api/admin/users/{id}/billing-hold/clear`). A reversed chargeback restores exactly what it took, once (`refund_restore`). Partial refunds, open requests and chargeback warnings freeze the lot and surface `review`; credits and tax corrections remove nothing. Migration `0012` (expand-only): new credit reasons, `billing_hold`, lot reversal markers, `billing_adjustment`. Erasing an account that bought a pack no longer fails: the purchase (an accounting record) drops its reference to the erased ledger row first. Operator action: run `make migrate`
- Paddle webhook and grant (RM-218): `POST /api/webhooks/paddle` verifies `Paddle-Signature` on the raw body (5 s tolerance, secret rotation via `PADDLE_WEBHOOK_SECRET_PREVIOUS`, 256 KiB cap) before anything is parsed, stores the event durably (migration `0011`, expand-only: `billing_event`, unique per environment and event id) and answers 200 for duplicates and 5xx on a database failure; it is the only route exempt from the Origin check, now by exact path. Billing jobs on the ops lane (`process_billing_events`, a one-minute `billing_sweep`) lease pending events (`SKIP LOCKED`), read the transaction fresh from Paddle and grant the pack's own report count exactly once (`paddle:{env}:{txn}:grant`, a lot linked to the purchase) only when price, quantity one, PLN total, no discount or subscription and our binding token all match; anything else is `review`. Missed notifications, ambiguous creations and a dead worker are recovered by reconciliation; a transaction refunded before its grant grants nothing. New problem code `INVALID_WEBHOOK_SIGNATURE` (400), settings `PADDLE_WEBHOOK_SECRET_PREVIOUS`, `PADDLE_WEBHOOK_TOLERANCE_S`, `RETENTION_BILLING_EVENT_DAYS` (90). Operator action: run `make migrate`; register the notification destination in Paddle only with the sandbox first (docs/PADDLE-INTEGRATION.md section 2)
- Report-pack checkout (RM-217): `GET /api/billing/packs`, `POST /api/billing/checkout` (body `{pack_code}` plus an `Idempotency-Key` UUID; 5 per minute and 20 per hour per user), `GET /api/billing/purchases` and `/{id}` (own purchases only, foreign ids 404). Migration `0010` (expand-only): `billing_pack` (immutable catalog versions) and `billing_purchase`. The intent is committed before Paddle is called; one transaction per request key; a creation that timed out is recovered by its purchase reference and binding token and never repeated. New problem codes `BILLING_UNAVAILABLE` (503, billing off: the default), `IDEMPOTENCY_CONFLICT` (409), `BILLING_PROVIDER_ERROR` (502). Nothing is granted yet (signed webhook: #218). Operator action: run `make migrate`; sales stay off until `BILLING_PROVIDER=paddle` and the owner-approved catalog are set
- Report credit lots (RM-216): migration `0009` (expand-only) adds `report_credit_lot` and `report_credit_allocation`. Every grant (signup, admin, later purchases) gets a lot; a reservation holds units from the oldest spendable lots and a release returns them to the same lots; existing balances become one explicit `migration` lot per account (granted = balance + in-flight + consumed + operator-removed, in-flight reservations get allocations). Lots explain the cached balance but are not a second balance authority; the nightly `ledger_check` now also compares lots and allocations. A fixed lock order (user advisory lock, `credit_account`, lots, audit) is enforced in `reserve`, `settle`, the worker finish and the reconciler. Frozen lots stay in the balance but cannot be spent (used by refunds in #219). No API change. Operator action: run `make migrate`
